# Segurança
Ative revisão específica para authn/authz, IAM, secrets, dados sensíveis, input externo, SQL, upload/download, rede, dependências, criptografia e logs.
Modelo mínimo: ativo → trust boundary → ameaça → controle → evidência.
Procure ampliação de privilégio, exposição, validação insuficiente, vazamento e falha segura.
Teste negativo pertinente é melhor que checklist genérico.
Ausência de finding não prova segurança.
